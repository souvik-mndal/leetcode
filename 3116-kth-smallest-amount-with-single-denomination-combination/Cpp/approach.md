## Problem Explained

You are given a list of distinct positive coin values and a target position `k`. 

Each coin can generate any positive multiple of its value. For example:
* A coin of value 3 produces: 3, 6, 9, 12, 15, and so on.
* A coin of value 5 produces: 5, 10, 15, 20, and so on.

You cannot combine different coins together (for instance, you cannot add 3 and 5 to make 8). You only take multiples of individual coins.

If you merge all the amounts generated by all coins into a single combined list, remove all duplicate numbers, and sort them from smallest to largest, your goal is to find the number at position `k` (1-indexed).

### Example
If `coins = [5, 2]` and `k = 7`:
* Multiples of 2: 2, 4, 6, 8, 10, 12, 14, 16...
* Multiples of 5: 5, 10, 15, 20...
* Combined unique list: 2, 4, 5, 6, 8, 10, 12, 14, 15...
* The 7th smallest amount in this list is **12**.

---

## Intuition

Generating and sorting all amounts up to `k = 2 * 10^9` is impossible because the list would be far too large to store in memory. Instead, we use three key ideas:

1. **Binary Search on the Answer:** 
   We guess a target amount `mid` and ask: *"How many unique coin amounts are less than or equal to mid?"* If the count is at least `k`, `mid` might be our answer or too large. If the count is less than `k`, `mid` is too small.

2. **Removing Redundant Coins:**
   If coin A divides coin B (e.g., 3 divides 6), then every multiple of 6 is already a multiple of 3. Coin 6 adds no new amounts! We can drop coin 6 completely. This keeps our active coin count `m` as small as possible.

3. **Inclusion-Exclusion Principle (Counting without duplicates):**
   To count how many valid amounts exist up to `x`:
   * For a single coin `c`, there are `x / c` multiples up to `x`.
   * Simply adding `x / c` for all coins double-counts numbers shared by multiple coins (e.g., 10 is counted by both 2 and 5).
   * To fix double-counting, we add counts for 1 coin at a time, subtract counts for pairs of coins using their Least Common Multiple (LCM), add counts for groups of 3 coins, subtract for groups of 4, and so on.

---

## Approach

* `sort(coins.begin(), coins.end());`: Sorts coin values in ascending order so smaller coins are evaluated first.
* `for (int coin : coins)`: Iterates through each coin to filter out redundant ones.
* `if (coin % prev == 0)`: Checks if the current coin is a multiple of an already accepted smaller coin in `useful`.
* `useful.push_back(coin);`: Adds the coin to `useful` only if it is not redundant.
* `long long high = useful[0] * 1LL * k;`: Sets the upper boundary for binary search. The `k`-th amount cannot be larger than `k` times the smallest non-redundant coin.
* `long long low = 1;`: Sets the lower boundary for binary search.
* `int m = useful.size();`: Stores the total number of useful non-redundant coins.
* `int totalMasks = 1 << m;`: Calculates `2^m`, the total number of non-empty coin combinations.
* `vector<long long> lcms(totalMasks, 1);` and `vector<int> signs(totalMasks, 1);`: Pre-allocates arrays to store the precalculated LCM and sign (+1 or -1) for every coin combination subset.
* `for (int mask = 1; mask < totalMasks; ++mask)`: Loops through all non-empty subsets of coins represented as bitmasks.
* `if (mask & (1 << i))`: Checks if the `i`-th coin belongs to the current subset `mask`.
* `long long g = std::gcd(currentLCM, useful[i]);`: Computes the greatest common divisor to calculate the updated LCM safely without overflow.
* `if (currentLCM > high / useful[i])`: Checks if the LCM will exceed `high`. If it does, caps it at `high + 1` to prevent arithmetic overflow.
* `signs[mask] = (bits % 2 == 1) ? 1 : -1;`: Assigns a positive sign (+1) to subsets with an odd number of coins, and a negative sign (-1) to subsets with an even number of coins.
* `auto count = [&](long long x)`: Defines a helper function that returns how many valid coin amounts exist in the range `[1, x]`.
* `result += signs[mask] * (x / lcms[mask]);`: Adds or subtracts `x / LCM` for each subset according to the Inclusion-Exclusion Principle.
* `while (low < high)`: Executes standard binary search to find the smallest number `mid` that satisfies `count(mid) >= k`.
* `return low;`: Returns `low`, which holds the exact `k`-th smallest valid amount once binary search completes.

## Dry Run

### Case 1: Standard input with redundant coins (`coins = [3, 6, 9], k = 3`)

**Filtering Step:**
* Sort coins: `[3, 6, 9]`
* Coin 3: Kept (`useful = [3]`)
* Coin 6: `6 % 3 == 0` -> Redundant (discarded)
* Coin 9: `9 % 3 == 0` -> Redundant (discarded)
* Final `useful = [3]`, `m = 1`, `high = 3 * 3 = 9`, `low = 1`.
* Subsets: `mask = 1` -> `LCM = 3`, `sign = +1`.

| Step | `low` | `high` | `mid` | `count(mid)` Calculation | `count(mid)` | Action |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 1 | 9 | 5 | `5 / 3 = 1` | 1 | `count(5) = 1 < 3` -> `low = 5 + 1 = 6` |
| 2 | 6 | 9 | 7 | `7 / 3 = 2` | 2 | `count(7) = 2 < 3` -> `low = 7 + 1 = 8` |
| 3 | 8 | 9 | 8 | `8 / 3 = 2` | 2 | `count(8) = 2 < 3` -> `low = 8 + 1 = 9` |
| 4 | 9 | 9 | - | - | - | `low == high`. Search ends. Output = 9. |

---

### Case 2: Multiple non-redundant coins (`coins = [5, 2], k = 7`)

**Filtering Step:**
* Sort coins: `[2, 5]`
* Coin 2: Kept (`useful = [2]`)
* Coin 5: `5 % 2 != 0` -> Kept (`useful = [2, 5]`)
* Final `useful = [2, 5]`, `m = 2`, `high = 2 * 7 = 14`, `low = 1`.
* Subsets:
  * Mask 1 (`useful[0] = 2`): `LCM = 2`, `sign = +1`
  * Mask 2 (`useful[1] = 5`): `LCM = 5`, `sign = +1`
  * Mask 3 (`useful[0]` and `useful[1]`): `LCM = 10`, `sign = -1`

| Step | `low` | `high` | `mid` | `count(mid)` Calculation | `count(mid)` | Action |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 1 | 14 | 7 | `7/2 + 7/5 - 7/10 = 3 + 1 - 0` | 4 | `count(7) = 4 < 7` -> `low = 7 + 1 = 8` |
| 2 | 8 | 14 | 11 | `11/2 + 11/5 - 11/10 = 5 + 2 - 1` | 6 | `count(11) = 6 < 7` -> `low = 11 + 1 = 12` |
| 3 | 12 | 14 | 13 | `13/2 + 13/5 - 13/10 = 6 + 2 - 1` | 7 | `count(13) = 7 >= 7` -> `high = 13` |
| 4 | 12 | 13 | 12 | `12/2 + 12/5 - 12/10 = 6 + 2 - 1` | 7 | `count(12) = 7 >= 7` -> `high = 12` |
| 5 | 12 | 12 | - | - | - | `low == high`. Search ends. Output = 12. |

## Time & Space Complexity

* **Time Complexity:** 
  * Filtering coins: `O(N^2)`, where `N` is the initial length of `coins`.
  * Precomputing LCMs: `O(m * 2^m)`, where `m` is the number of non-redundant coins (`m <= N <= 15`).
  * Binary Search: Runs in `O(log(min_coin * k))` steps. Each step calls `count()`, which loops over `2^m` subset masks.
  * Total Time: `O(N^2 + m * 2^m + 2^m * log(min_coin * k))`. With `m <= 15`, `2^15 = 32,768` operations per binary search step, completing in under 2 milliseconds overall.

* **Space Complexity:** `O(2^m)` to store the precalculated `lcms` and `signs` vectors for all subsets.

### Can it be improved?
Yes, precomputing LCMs for each mask currently loops `m` times. We can optimize precomputation to `O(2^m)` using **Dynamic Programming with Bit Manipulation**. 

Instead of recomputing the LCM from scratch for every mask, we can build `lcms[mask]` in constant `O(1)` time by combining the LCM of `mask` with its lowest set bit removed (`mask & (mask - 1)`) and the coin at that lowest bit index (`__builtin_ctz(mask)`).

```cpp
for (int mask = 1; mask < totalMasks; ++mask) {
    int prevMask = mask & (mask - 1);
    int bitIndex = __builtin_ctz(mask);

    // Flipping sign: adding one element toggles odd/even count
    signs[mask] = (prevMask == 0) ? 1 : -signs[prevMask];

    long long prevLCM = (prevMask == 0) ? 1 : lcms[prevMask];

    if (prevLCM > high) {
        lcms[mask] = high + 1;
    } else {
        long long g = std::gcd(prevLCM, useful[bitIndex]);
        long long nextLCM = prevLCM / g;

        if (nextLCM > high / useful[bitIndex]) {
            lcms[mask] = high + 1;
        } else {
            lcms[mask] = nextLCM * useful[bitIndex];
        }
    }
}
```

* **Improved Time Complexity:** `O(N^2 + 2^m + 2^m * log(min_coin * k))`
* **Improved Space Complexity:** `O(2^m)`

**Is this optimal?**
Yes. Counting unique set unions for arbitrary subsets is an established hard combinatorial problem. Because `m <= 15`, `2^m` is at most 32,768, which makes `O(2^m * log(min_coin * k))` the theoretical and practical optimal limit for this problem.

## Edge Cases Handled

* **Redundant Denominations:** Inputs like `coins = [3, 6, 9]` are reduced to `useful = [3]`, preventing zero-division, duplicate work, and unnecessary inclusion-exclusion terms.
* **Large Value of `k` (`k = 2 * 10^9`):** The output can reach `5 * 10^10`, exceeding standard 32-bit signed integers. The implementation uses 64-bit `long long` for `low`, `high`, `mid`, and `lcms` to avoid arithmetic overflow.
* **LCM Arithmetic Overflow:** Multiplying large numbers can easily overflow `long long`. The code prevents this by dividing by GCD first (`currentLCM = currentLCM / g`) and checking `currentLCM > high / useful[i]` before multiplying.
* **Single Coin Input (`coins.length = 1`):** Works correctly with `m = 1` and `totalMasks = 2`, giving the answer in `O(log k)` binary search steps.
